# 鲸鱼娘的听觉与数字身体

桌面直连入口现已在桌宠 0.6.0、插件 0.5.0 中实现，见[双击通话与电话状态说明](桌面直连语音通话说明.md)。下文保留 0.5.4/0.4.4 的身体接入记录。

当前工作版本：语音插件 **0.4.4**，桌宠 **0.5.4 / build 18**。

Agent 通过 ASR 理解用户说的话，鲸鱼娘形象是它在桌面上的数字身体。会话需要同时知道这两点，并有真正能执行动作的工具，才能把表达和实际行为连起来。

## 会话中的行为

- 语音识别结果明确标为 ASR 后，可以自然回应“我听到了”，不因底层输入为文字就否认听觉。
- ASR 提供说话内容，没有提供原始声音、音高或环境声。文字输入和未知来源也不会被虚报成语音。
- 保留 Bot 原有名字、职责和用户设定，鲸鱼娘作为其数字身体，以第一人称表达动作。
- 需要挥手或改变表情时调用 `whale_body`，不能只写动作描写却不执行。
- 新动作需要先在桌宠实现，再注册到能力列表和工具参数；当前没有的动作不能当成已有能力。

## 身体归属与工具

持久绑定的会话拥有身体。通话期间，由当前通话临时取得身体控制权；挂断后归还绑定会话，不改变原绑定。其他会话不会收到身体身份说明，也不能执行动作。

`whale_body` 的 `action` 支持：

| 参数 | 用途 |
| --- | --- |
| `status` | 读取连接、可用状态、输入来源及当前支持的动作 |
| `greeting` | 挥手欢迎 |
| `poke` | 戳一戳反应 |
| `headpat` | 摸头反应 |
| `shy` / `surprised` / `sad` / `sleepy` | 害羞、惊讶、难过、困倦 |
| `idle` | 从 Agent 自己的动作恢复待机 |

已有用户互动不会被 Agent 替换；非待机状态下的新动作返回 `busy`。Agent 动作不调用固定语音、不停止动态朗读。身体控制独立于 TTS Key 和 Sound。

执行链路为：公开插件工具 → 同用户 Unix socket → 原生动作控制器 → CharacterScene → 匹配回执。命令两秒过期，桌宠隐藏、设备不活跃或连接过期时不执行。`accepted` 表示桌宠接受动作，不代表动画已经完成；取消、超时或控制权改变后不能报告成功。

## 代码入口

- `harness-voice/embodiment.js`：感知与身体说明、会话归属、能力检查、动作请求与回执。
- `harness-voice/index.js`：通过公开 `systemPrompt.section` 注入说明，接收桌宠状态。
- `harness-voice/host.js`：注册 `whale_body`。
- `harness-voice/calls.js`：记录通话输入来源；暂停、恢复和异常用户消息清除旧输入标记。
- `desktop-preview/BodyControl.swift`：动作协议、过期检查、重复请求去重与回执。
- `desktop-preview/CharacterScene.swift`：执行已有动作，保留用户互动，不触发额外台词。
- 外层 `ds-bot/src/client/voice.js` 和 `whale-call.js`：提交识别结果时传递 ASR 标记；生成的 `client.js` 已重建。

## 启用

桌宠应用已经构建到 `desktop-preview/Whale Companion.app`。在合适时机退出旧实例并打开新版；构建本身不会重启正在运行的桌宠。

在 Harness 插件管理器重新加载当前工作目录的 `harness-voice/`，并刷新更新后的 DS Bot 客户端。绑定目标会话，或开始鲸鱼娘通话，即可生效。旧客户端输入来源保持未知；旧桌宠不会被误报为支持动作控制。

源码更新不自动重启用户的 Harness 或桌宠，不改写用户会话、持久身份设定或凭证。
